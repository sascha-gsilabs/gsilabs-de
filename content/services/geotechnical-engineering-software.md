  - type: pillars
    eyebrow: What we build
    title: >-
      Geotechnical software fails on the details. The soil model, the partial factors,
      the annex that applies in one country and not the next.
    lede: >-
      Generic engineering tools treat geotechnics as one more load case. The result is
      software that cannot express what a borehole log actually says, or that produces
      numbers an engineer has to redo by hand before signing anything. We build in this
      field, so the details that decide whether a tool is usable are the ones we start
      from.
    items:
      - title: Statistical Soil Modelling
        body: >-
          Borehole data turned into probabilistic layer models rather than one
          conservative profile, so a design can be evaluated against the ground as it was
          actually measured.
      - title: Design Optimization
        body: >-
          Engines that evaluate thousands of configurations against structural
          requirements and return the leanest one that holds, with the reasoning attached.
      - title: Code Compliant Output
        body: >-
          Calculations that follow EA Pfähle and Eurocode 7 with the relevant national
          annexes, and documentation an engineer can put their name to.
    note: >-
      * On pilot projects in Germany, optimized designs have come in around 25 percent
      lighter on material. What a given project achieves depends on ground conditions and
      design constraints.

    items:
      - title: Start From the Calculation
        body: >-
          Before any interface exists we work through the engineering with your team:

          be allowed to output. This is where geotechnical software is won or lost, and

      - title: Build It Where Your Work Already Is
        body: >-

          arrive in, the reporting your clients expect, and the systems you already run,
          whether that is a desktop application, a plugin inside an authoring
          environment, or a service your other tools call.
      - title: Validate Against Real Projects
        body: >-
          Every calculation path is tested against projects you have already delivered,
          where the answer is known. Your engineers review the output and sign it off
          before anything is used in anger. We iterate until the numbers hold up, then we
          keep maintaining them as the standards move.
