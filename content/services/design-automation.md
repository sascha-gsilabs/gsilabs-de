  - type: pillars
    eyebrow: What we build
    title: >-
      A large share of design office time goes on work that follows rules somebody could
      write down. That is the work worth automating.
    lede: >-
      Placing components to a standard detail, generating drawing sets, renaming and
      renumbering, checking a model against an office standard: none of it needs
      judgement, all of it needs doing, and it lands on qualified engineers. We build the
      tools that take it off their desks, inside the software they already use rather
      than beside it.
    items:
      - title: Plugin Development
        body: >-
          Tools that run inside Revit, Tekla, Allplan or Archicad, using their APIs, so
          nobody has to export a model or learn a second application to get the benefit.
      - title: Standards Compliance
        body: >-
          Your office standards, naming conventions and detailing rules encoded into the
          tool, so the output is correct by construction rather than corrected in review.
      - title: Continuous Updates
        body: >-
          Authoring tools change every year. We maintain what we build against new
          releases so a plugin does not quietly become the reason you cannot upgrade.
    note: >-
      * On automated workflows, teams have reported drawing production several times
      faster. What a given office gains depends on how much of its work is rule based.

  - type: stages
    id: how
    title: How we work on it
    items:
      - title: Find What Is Actually Repetitive
        body: >-
          We sit with the people doing the work and watch how a project really moves
          through the office. Which steps repeat on every job? Where does the same
          correction get made twice? Not everything that feels tedious can be automated,
          and some things that can are not worth it. The output is a ranked list, with
          the effort and the payback next to each item.
      - title: Build Inside the Authoring Tool
        body: >-
          We develop against the API of the software you use, so the tool appears where
          your team already is: a ribbon button, not a separate application. It reads
          your models, respects your templates, and writes back in a form the rest of
          your process understands.
      - title: Roll Out and Maintain
        body: >-
          A plugin gets tested on live projects with the people who will use it, then
          rolled out across the office with the documentation to go with it. After that
          we keep it current as the authoring tools release new versions and as your
          standards move.

  - type: statement
    title: The point is not clever software. It is drawings out the door.
    body: >-
      Automation in design offices fails when it produces output somebody still has to
      check line by line. We build so the result is trusted: rules taken from your own
      standards, tested on your own projects, with the cases the tool will not handle
      made explicit rather than guessed at.
    points:
      - Runs inside the authoring tool, so nothing has to be exported or relearned
      - Your office standards encoded, so output is right the first time
      - Maintained against new releases, so automation never blocks an upgrade
